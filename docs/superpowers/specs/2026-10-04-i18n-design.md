# 多语言（中 / 英）支持 — 设计

日期：2026-10-04
状态：待实现

## 背景与动机

mdbox 现有全部文案（前端界面、后端错误、MCP 工具描述）都是中文写死的。作者计划去英文社区推广，英文访客第一次打开网站（登录页、注册、主界面、弹窗、分享页）看到的必须是英文，并且能一键在英文 / 中文之间切换。

当前不存在任何 i18n 机制：搜索 `locale|lang|i18n|Accept-Language` 在 Go 与前端均无结果，`web/index.html` 固定写 `<html lang="zh-CN">`。

## 目标

- 浏览器端所有用户可见文案支持中 / 英两种语言。
- 首次访问按浏览器语言自动选择，之后记住用户选择。
- 顶栏（切换主题图标旁）提供一个语言切换图标，在中 / 英之间切换。
- 后端返回给前端的错误文案随界面语言变化。
- MCP 工具描述与结果统一为英文（面向 agent）。
- 保持产品一贯的克制风格：vanilla、零依赖、不自造构建工具、无数据库。

## 非目标

- **不翻译部署者视角的字符串**：CLI flag 帮助、启动 / 致命日志（`main.go`）、生成的 `config.yaml` 注释（`internal/config`）。这些仅部署者可见。
- **不翻译文档内容本身**（用户数据）。
- 不做 URL 语言前缀 / 独立 SEO 页面 / 第三门语言；但键值结构上留出扩展位置。
- 不引入任何前端依赖或构建步骤。
- 不改变任何既有业务行为（认证、存储、分享、MCP 协议语义）。

## 决策摘要

| 项 | 结论 |
|---|---|
| 覆盖范围 | 浏览器 UI + 后端 API 错误 + MCP 工具文案 |
| 默认语言 | 自动识别：`localStorage` → `navigator.language`（`zh*`→中文，其余→英文）→ 英文兜底 |
| 语言持久化 | `localStorage['mdbox:lang']`，取值 `zh` / `en` |
| 切换入口 | 应用顶栏 `#lang-btn`（地球 SVG，位于主题按钮右侧）、登录页右上角 `#login-lang-btn`、分享页顶栏 `#share-lang-btn`；窄屏仍显示 |
| 前端方案 | 新增 `web/i18n.js` 字典 + `data-i18n*` 静态重写 |
| 后端方案 | 新增 `internal/i18n` 消息目录；哨兵错误改为携带「键」；`writeErr` 按请求 `Accept-Language` 翻译 |
| 语言传递 | 前端所有请求带 `Accept-Language: <当前语言>` |
| MCP 语言 | 固定英文（当前选中方案） |
| 默认标题 | `internal/store` 的 `未命名文档` → `Untitled`；Web 创建时由前端传本地化标题 |

## 详细设计

### 1. 语言代码与解析

- 内部语言代码统一用 `zh` / `en`（不带地区）。
- 前端 `<html lang>`：`zh` → `zh-CN`，`en` → `en`。
- 后端 `internal/i18n.FromAcceptLanguage(header)`：取 `Accept-Language` 中第一个可识别语言，前缀 `zh` → 中文，其余 / 空 → 英文。**默认英文**（面向英文推广）。

### 2. 键命名约定

- 全部小写、点号分命名空间：`<域>.<项>`，如 `login.submit`、`nav.categories`、`user.change_password`、`doc.untitled`。
- 后端错误键与前端 UI 键共用同一命名空间，但后端错误不需要前端再映射——见 §5。
- 前端字典与后端目录**键集合必须一致**（由单测保证，防漏译）。

### 3. 前端

**新增 `web/i18n.js`**（在 `app.js` 之前引入；`//go:embed web` 自动打包、`staticFiles` 自动 gzip）

- 导出全局 `I18N`：
  - `I18N.t(key, vars)`：查 `zh`/`en` 字典，`{name}` 占位符做简单替换；缺键时回退到另一语言，再回退到键名本身。
  - `I18N.lang()` / `I18N.setLang(l)`：读写 `state.lang` 并持久化到 `localStorage['mdbox:lang']`。
  - `I18N.applyStatic(root)`：遍历 `[data-i18n]` → `textContent`；`[data-i18n-title]` → `title`；`[data-i18n-placeholder]` → `placeholder`；`[data-i18n-aria]` → `aria-label`。并同步 `<html lang>` 与 `document.title`。
- 语言初始解析顺序：`localStorage` → `navigator.language` → `en`。

**`web/index.html`**

- 所有静态文案加 `data-i18n*` 属性（登录页、分享页、主应用顶栏 / 侧栏 / 列表空态、5 个弹窗、分享弹窗）。
- 顶栏在 `#theme-btn` 之后、账号下拉之前插入 `#lang-btn`（`.icon-btn` + 地球 SVG）。顺序：`MCP · 主题 · 语言 · 账号`。
- 语言切换按钮共有三处，均为同款地球 SVG：应用顶栏 `#lang-btn`；登录页右上角 `#login-lang-btn`（绝对定位）；分享页顶栏 `#share-lang-btn`（紧随 `#share-theme-btn`）。后两处的 tooltip 由 JS 动态设置，不加 `data-i18n-title` / `data-i18n-aria`。
- `title` 属性（tooltip）也走 `data-i18n-title`，随语言变化（如 `Switch to English` / `切换为中文`）。

**`web/app.js`**

- 约 50 处动态文案改为 `I18N.t(...)`（侧栏「全部文档 / 暂无标签」、列表计数与状态、对话框默认按钮、登录切换、分享页错误与标题、上传 / 下载 / 导出提示等）。
- 所有 `fetch`（`api()`、上传、下载、分享）加 `Accept-Language: I18N.lang()` 头。
- `#lang-btn` 点击：切换语言 → `I18N.applyStatic()` → 重渲染当前视图（侧栏、列表、顶栏用户名 / 头像不变；文档预览态重渲染 meta）。
- **切换语言不触碰编辑态 `#d-source` / `#e-title` / `#e-category` / `#e-tags` 的内容**——只更新工具条按钮等静态文案，避免丢失未保存输入。

### 4. 后端 `internal/i18n`

- `type Lang string`，常量 `ZH` / `EN`，`Default = EN`。
- `func FromAcceptLanguage(h string) Lang`。
- `type Key string` + 键常量集中定义。
- `func T(l Lang, k Key) string`：查 `map[Lang]map[Key]string`；缺翻译回退英文，再回退键名。
- `func Known(k string) bool`：判断某字符串是否为已知键（供 `writeErr` 决定翻译还是原样输出）。

`internal/i18n` 不 import 任何内部包，`users` / `store` / `api` / `mcp` 均可依赖它，无循环依赖。

### 5. 后端错误本地化

**哨兵错误改为键**（保留变量与 `errors.Is` / `==` 语义，既有测试不受影响）：

| 变量 | 旧文案 | 新键 |
|---|---|---|
| `users.ErrInvalidName` | 用户名只能包含… | `user.name_invalid` |
| `users.ErrWeakPassword` | 密码长度需要在… | `user.password_weak` |
| `users.ErrExists` | 用户名已被占用 | `user.exists` |
| `users.ErrNotFound` | 用户不存在 | `user.not_found` |
| `users.ErrWrongPassword` | 旧密码不正确 | `user.password_wrong` |
| `store.ErrNotFound` | `doc not found` | `doc.not_found` |

**`internal/api`**：

- `withAuth` 在**最顶部**（含 public 路径）解析 `FromAcceptLanguage(r.Header.Get("Accept-Language"))` 并写入 `context`。
- `writeErr(w, r, status, msg)` 增加 `*http.Request` 参数：`msg` 是已知键 → 按请求语言翻译；否则原样输出。调用点全部改为传 `r`。
- 各 handler 的固定中文改为键：`auth.bad_credentials`、`auth.register_closed`、`auth.register_limited`、`share.gone`、`error.bad_json`、`error.bad_form` 等。
- `bad json` / `parse form`：对外返回本地化的「请求格式错误 / Invalid request」，**原始错误写日志**，不拼进响应（避免泄露内部细节，也避免拼接中英混排）。
- `main.go` 的 `/mcp` handshake 错误（`unauthorized`）保持英文（agent 面，非浏览器）。

### 6. MCP（`internal/mcp`）

- 全部工具描述、参数描述、结果 `message` 改为英文（`list_docs`、`search_docs`、`read_doc`、`write_doc`、`update_doc`、`list_tags`、`archive_doc`）。
- `toolErr` 对已知键解析为**英文**文案后再返回。
- 工具名（`list_docs` 等）本就是英文标识符，不动。

### 7. 默认标题

- `internal/store` 的默认标题 `未命名文档` → `Untitled`（该路径主要由 MCP / agent 触发，MCP 已定为英文）。
- Web 端 `createDoc` 已显式传标题，改为传 `I18N.t('doc.untitled')`，随界面语言。

### 8. 分享页

- 复用同一套 `i18n.js` 与 `data-i18n`；匿名访客按 `navigator.language` 决定语言。
- 分享读取失败（`分享不存在或已失效`）由后端按 `Accept-Language` 返回，前端直接展示。
- 分享页 `<title>`（`<标题> · MDBox`、`分享 · MDBox`）本地化。

## 实现顺序（建议）

改动面广，按层推进、每步可独立验证：

1. **后端骨架**：新增 `internal/i18n`（含单测）；`users` / `store` 哨兵错误改键；`api` 注入语言 + `writeErr` 改造。此时后端错误已能按 `Accept-Language` 本地化。
2. **前端基础设施**：`web/i18n.js` + `index.html` 的 `data-i18n` + `#lang-btn` + `app.js` 请求头与静态重写。此时静态界面可切换。
3. **前端动态文案**：`app.js` 内动态字符串改 `I18N.t`。
4. **MCP**：`internal/mcp` 改英文 + `toolErr` 解析。
5. **收尾**：默认标题、分享页 `title`、人工冒烟。

## 边界与注意事项

- 前端经 `//go:embed web` 打包，**改完必须重新构建**才生效；`*.js` 在 `.gitattributes` 中标记为 `binary`，diff 不显示内容属正常。
- `writeErr` 签名变更会触及所有调用点，需一次性改全，避免遗漏导致编译失败。
- 语言切换在编辑态下**必须**保护未保存内容（见 §3）。
- 缺翻译时回退英文 / 键名，不抛异常、不留空白。
- 目录键集合一致性由单测守护（中英键必须一一对应）。

## 验证方式

- 构建门禁：`gofmt`（新增代码）、`go vet ./...`、`go test ./...`、`go build` 全过。
- `internal/i18n` 单测：`FromAcceptLanguage`（`zh-CN,zh;q=0.9`→中文；`en-US`→英文；空→英文）与中英目录键集合相等。
- 现有 `internal/users` 测试保持绿。
- 浏览器人工验收（作者本人）：
  - 清空 `localStorage` 用英文 / 中文浏览器分别首次打开，默认语言正确。
  - 顶栏语言图标切换：登录页、主界面、侧栏、5 个弹窗、分享页文案全部跟随；编辑态输入内容不丢。
  - 后端错误（重复注册、密码太短、错误密码、失效分享）在中 / 英两种界面语言下文案正确。
  - `<html lang>` 与各视图 `document.title` 正确。
  - 深浅色主题、窄屏下语言按钮可见可用。
