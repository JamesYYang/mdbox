# 登录页宣传与品牌一致性 — 设计

日期：2026-10-02
状态：已实现（2026-10-02）

## 背景与动机

mdbox 目前能跑、也绑好了 `www.mdbox.tech`，但对外"能见人"的程度不够：

1. 只有一个产品名 `MDBox`，没有一句话说清它是做什么的。
2. 网站打开直接进登录，而登录页只有一句"请登录后使用"，陌生人第一次进来不知道这是什么。
3. 三个视图（登录 / 分享 / 主应用）左上角的品牌不可点击，无法回到站点首页或文档列表。
4. 产品定位为**公开在线服务**（任何人注册即用），但既有文案写的是"自托管的 Markdown 知识库"——用词与定位不符。

目标是让第一次进来的人**三秒内知道这是什么**，同时保持产品一贯的克制风格（vanilla、零依赖、不自造轮子）。

## 目标

- 给产品名配一句 slogan。
- 把登录页从"光秃秃的登录卡片"升级为"讲清产品 + 登录"的落地页。
- 让品牌可点击，行为符合各视图语义。

## 非目标

- 不动任何 Go 后端、路由、认证、API。
- 不做营销页 / 独立 landing page、不做截图、不做多语言。
- 不引入任何前端依赖或构建工具。
- 主应用顶栏**不加** slogan（登录后的用户已知产品），仅登录页与分享页加。

## 决策摘要

| 项 | 结论 |
|---|---|
| slogan | **人写，Agent 也写** |
| slogan 位置 | 登录页（融进定位句）+ 分享页品牌旁；主应用顶栏不加 |
| 登录页布局 | **布局 A · 左右两栏**（左宣传 / 右登录卡），窄屏堆叠 |
| 登录页内容 | 定位句（含 slogan）+ 2 条特性要点 + 1 条 MCP 说明（无截图） |
| 品牌点击 | 主应用→文档列表；分享页→站点首页 `/`；登录页不响应 |
| 文案存储 | 直接静态写在 HTML 两处（方案 A），不走 JS 注入 |

## 详细设计

### 最终文案

- **品牌行（登录页）**：`MDBox`（不含 slogan——slogan 已融进定位句，避免同一列里重复出现两次）
- **品牌行（分享页）**：`MDBox` · `人写，Agent 也写`
- **定位句**：`你的 Markdown 知识库，人写、Agent 也写`
- **特性要点**（2 条）：
  - 纯 `.md` 文件存储，随时导出带走
  - 一键只读分享
- **MCP 说明**（单独一行，强调色）：`让 Agent 通过 MCP 直接读写你的库`

统一约定：宣传文案中 `Agent` 一律首字母大写（与 slogan 一致）。

**定位说明（2026-10-02 修订）**：mdbox 对外定位为**公开在线服务**（任何人可注册使用），而不是「自托管软件」。因此文案刻意回避「自托管」「存在你自己的磁盘」「没有数据库 / 一个二进制」这类**部署者视角**的说法——它们对访客要么不成立、要么看不懂。

### 1. 登录页（布局 A · 左右两栏）

把 `#view-login` 由「居中单卡片」改为一个两栏容器：

- **左栏 `.login-promo`**（纯文本，无交互）
  - 品牌行：`MDBox`
  - 定位句
  - 特性要点（`<ul>`，小圆点）
  - MCP 说明（强调色单独一行）
- **右栏 `.login-card`**：**去掉卡片内的品牌行**（`.login-brand`）——品牌统一由左栏承担，避免两栏里出现两个 `MDBox`。`login-tip`、用户名/密码/再次密码输入、提交按钮、`login-msg`、`没有账号？注册` 切换按钮**全部不动**，其 DOM 结构与 `app.js` 里 `login-*` 相关逻辑保持一致，避免破坏注册/登录流程。

实现要点：

- 布局用 CSS Grid：桌面端两列（左栏略宽，如 `1.2fr / 320px`），窄屏单列。
- 沿用现有 `@media (max-width: 720px)` 断点，在该断点下改为上下堆叠：**宣传在上、卡片在下**。
- 所有颜色用既有 CSS 变量（`--bg / --surface / --border / --text / --muted / --accent`），保证深浅色主题都正确。
- `.login-wrap` 仍保持整屏居中；两栏整体在竖直、水平方向居中。

### 2. 分享页

- `.topbar` 内的 `.brand` 追加 slogan：`MDBox · 人写，Agent 也写`（slogan 用次要色、字号略小于产品名，不抢只读正文）。
- 分享页其余结构、只读逻辑不动。

### 3. 品牌点击

| 视图 | 行为 |
|---|---|
| 主应用 | 点品牌 → 回到**文档列表**（等价现有"返回"，但不留多余历史记录） |
| 分享页 | 点品牌 → 跳转**站点首页 `/`**（即登录页） |
| 登录页 | 品牌位于卡片中央，**不绑定点击** |

实现要点：

- 主应用：复用既有回列表逻辑（`showContent('list')` + 载入列表；若当前在文档页，按现有 `leaveDocUrl()` 语义处理地址栏，不产生多余历史）。
- 分享页：`location.href = '/'`（或 `location.assign('/')`）。
- 视觉：可点击品牌加 `cursor: pointer` 与 hover 反馈；登录页品牌不加。

## 涉及文件

| 文件 | 改动 |
|---|---|
| `web/index.html` | 登录区改为两栏 + 新增 `.login-promo`；分享页 `.brand` 加 slogan；为主应用/分享页品牌补绑定所需的选择器 |
| `web/style.css` | `.login-wrap` 改 Grid；新增 `.login-promo` 样式；`720px` 断点下堆叠；品牌可点样式；分享页 slogan 样式 |
| `web/app.js` | 绑定主应用品牌点击（回列表）与分享页品牌点击（跳 `/`）；登录页不绑 |

**不改**：`main.go`、`internal/**`、路由、认证、API、文案以外的任何后端行为。

## 边界与注意事项

- 前端经 `//go:embed web` 打包，**改完必须重新构建**才生效。
- 登录卡片 DOM 尽量少动，降低破坏登录/注册流程的风险；新增内容集中在 `.login-promo`。
- 窄屏下确保宣传区不会把登录卡片挤出首屏——堆叠时宣传在上，卡片应仍可见；必要时压缩宣传区字号/行距。
- 不做图片，纯文字 + 现有图标，符合"零依赖、无 CDN"约束。

## 验证方式

- 构建门禁：`gofmt`（新增代码）、`go vet ./...`、`go test ./...`、`go build` 全过。
- 浏览器人工验收（作者本人）：登录页两栏 / 窄屏堆叠、分享页 slogan、三处品牌点击行为、深浅色主题。
