# mdbox 产品需求文档（PRD）

> 版本 v0.3 · 2026-10-02 · 状态：MVP + 体验增强已交付，自用验证中
> 作者：与 CodeBuddy 多轮讨论后的产物

---

## 1. 背景与问题

### 1.1 现状痛点

当前工作流中，大量讨论、调研、决策是通过与 AI agent 对话完成并落盘为 Markdown 文件的。这些文件：

- **散落在各处**：不同会话的工作目录、下载目录、临时文件夹
- **无法被再次消费**：想回顾某个历史决策时，找不到或记不清在哪
- **没有生命周期**：三个月前的技术方案和昨天的笔记混在一起，时效性全靠人脑判断
- **访问受限于设备**：仅存在某台机器上，换设备就看不了
- **与产出端脱节**：agent 写完了，人还要手动搬运、整理、上传

### 1.2 为什么现有工具解决不了

| 现有方案 | 能解决的部分 | 解决不了的部分 |
|---|---|---|
| NotebookLM（Google） | 上传文档 + 基于文档问答，回答带逐句引用 | 要手动上传；只进不出，无衰减/过期机制；无开放 API |
| 腾讯 IMA | 支持 md 上传、知识库问答、OCR、多端同步、微信生态导入 | 同样需要手动搬运；无生命周期管理；内容托管在平台 |
| Obsidian / Typora | 文件在自己手里，编辑体验好 | 无 Web 协作，换设备麻烦，AI 能力靠第三方插件拼 |
| HedgeDoc / Docmost / Outline | Web 端多人实时协作 | 需要服务器 + Postgres/Redis 等重依赖；面向团队 wiki，非个人归档场景 |
| AnythingLLM / Cherry Studio | 自建 RAG，文档问答 | 部署配置成本高；本质仍是"上传 + 问答" |

**核心结论**：所谓"上传 + 归类 + AI 问答"这三项能力，2026 年已经被完全商品化且多数免费。在这个维度上做任何投入都是重复造轮子。

### 1.3 真正的机会点

市场留下两个没人做的空档：

1. **生命周期 / 保鲜度管理** —— 所有工具都假设"存了就是资产"，默认永久累积。但 agent 产出的讨论稿是**衰减最快的一类内容**：一次技术选型讨论，三个月后就是噪音。没有任何主流工具处理这件事。
2. **让知识库接进 agent 的工作流** —— 现有工具都是"人喂给 AI"的单向通道。反过来，让 agent 能自主读写这个库（通过 MCP），产出端和消费端就能闭环，**手动上传这一步被彻底消灭**。

## 2. 产品定位

### 2.1 一句话定位

> **mdbox 是 agent 的记忆层：让 agent 产出的 Markdown 自动归档入库，人随时用浏览器阅读与编辑，agent 随时通过 MCP 读写。**

关键在"agent 的记忆层"这个措辞——**不是又一个 AI 知识库**。区别在于：不做自己的问答界面、不做自己的向量检索、不做模型。AI 能力由使用者的 agent（CodeBuddy / Claude / Cursor 等）提供，mdbox 只负责提供可靠的知识底座。

### 2.2 目标用户

**首要用户画像**：高频使用 AI agent 处理知识工作的开发者与产品负责人

- 每周产出数十份 md（方案讨论、调研报告、代码审查结论、竞品分析）
- 已经有一套 agent 工具链，缺的是产出物的归口
- 在意数据主权，不愿意把思考过程托管给第三方平台
- 习惯 Git 工作流，接受 GitHub/GitLab 作为存储后端

**次要用户**：小团队（2–10 人）共享技术文档与决策记录。

### 2.3 明确非目标

以下事项**刻意不做**，每一次都要抵抗住"加上这个功能会更完整"的诱惑：

- ❌ 自己的向量数据库与 embedding 流程
- ❌ 自己的 AI 问答界面（NotebookLM / IMA 已免费提供）
- ❌ 自有存储服务（用磁盘目录 + Git；文档不托管到对象存储）
- ❌ 移动端原生 App（Web 响应式已够用）
- ❌ 富文本所见即所得编辑器（保留 Markdown 源码的纯粹性）
- ❌ **权限体系与跨用户协作**：多用户只做到「各用户文档隔离」；不做角色、协作权限、用户间共享文档、找回/改密码流程
  （*v0.1 为"不做账号体系"；v0.2 引入单管理员登录；v0.3 引入多用户自助注册，用 `users.yaml` 单文件管理，仍不引入数据库，权限分级与协作仍不做*）

## 3. 差异化

| 维度 | mdbox | NotebookLM | 腾讯 IMA | HedgeDoc |
|---|---|---|---|---|
| 文档存储位置 | 自有磁盘 / 私有 Git 仓库 | Google | 腾讯 | 自托管 DB |
| 数据来源 | agent 自动写入 / 手动上传 | 手动上传 | 手动上传 | 手动编辑 |
| 面向谁的界面 | 人（Web）+ agent（MCP） | 人 | 人 | 人 |
| Markdown 原生编辑 | ✓ 只读预览 + 双栏编辑 | ✗ | 部分 | ✓ |
| 免登录只读分享 | ✓ 固定链接 | 部分 | 部分 | ✓ |
| 生命周期管理 | P1 规划（核心差异化） | ✗ | ✗ | ✗ |
| 可自托管 | ✓ 单二进制 | ✗ | ✗ | ✓（重依赖） |

**信任卖点**："我们不托管你的数据，文档永远是纯文本，工具只是一个可以卸载的视图。"

## 4. 功能需求

### 4.1 P0 —— MVP（已交付）

| 编号 | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| P0-1 | 文档存储 | md 文件 + YAML frontmatter 落盘，ID 命名，活跃区/归档区分离 | 每篇文档可脱离工具单独阅读；外部删改文件后索引自动重建 |
| P0-2 | 元数据 | title / tags / category / source / status / shared / created / updated | 标签支持中文；可按标签、分类、状态过滤 |
| P0-3 | Web 列表 | 左侧栏（分类 / 标签 / 归档）+ 卡片列表 + 全文搜索 | 中文全文搜索可用；窄屏自适应 |
| P0-4 | Web 编辑 | **默认只读预览**，点「编辑」进入双栏（左源码右实时预览），可改标题/分类/标签；Ctrl/Cmd+S 保存，未保存离开有提示 | 输入后 300ms 内刷新预览；表格/代码块渲染正确 |
| P0-5 | 上传 / 下载 | 拖拽或选择多个 .md 上传；单篇下载为 .md | 上传时沿用文件自带 frontmatter 的标题与标签 |
| P0-6 | REST API | 覆盖登录、文档 CRUD、搜索、标签/分类聚合、multipart 上传、Markdown 渲染、分享 | 全端点通过冒烟测试（见第 7 节） |
| P0-7 | MCP Server | 7 个工具，支持 HTTP（Streamable）与 stdio 双传输 | agent 可独立完成写入—检索—读取闭环 |
| P0-8 | 鉴权 | Web 用登录会话（Cookie）；agent/脚本用**用户自己的 token**（注册时自动生成，可重置）。会话与 token 都解析成用户，`/api`、`/mcp` 只能访问该用户自己的文档；`/mcp` 仅认 token | 未登录访问 Web 被拦到登录页；A 用户的会话/token 读不到 B 用户的文档 |
| P0-9 | Git 自动备份 | 数据目录 git 化 + crontab 定时提交推送 | 无变更不产生空提交；推送失败不影响服务 |

### 4.2 v0.2 —— 体验增强（已交付）

| 编号 | 功能 | 说明 |
|---|---|---|
| V2-1 | **登录** | Web 用户名/密码登录，会话存内存，重启需重登。v0.3 起账号来自 `users.yaml`（见 V3-1），`config.yaml` 的 admin 仅用于首次初始化 |
| V2-2 | **顶栏与布局** | 顶栏：产品名 + Logo、MCP 接入弹窗、浅色/深色主题切换、用户信息与退出；正文区改为「左菜单（分类/标签/归档）+ 右内容」布局 |
| V2-3 | **只读预览为主** | 打开文档默认只读渲染，点「编辑」才进双栏模式，降低误编辑 |
| V2-4 | **文档分享** | 每篇可手动开启，生成**固定算法**的稳定链接 `/s/<user>/<id>/<sig>`（`sig = HMAC-SHA256(secret, user/id)[:24]`）；匿名免登录**只读**，可随时关闭撤销；改 `secret` 使全部链接失效 |
| V2-5 | **导出** | 预览模式可下载 `.md`，或导出 PDF（浏览器端 html2pdf，**本地内置、不依赖 CDN**） |
| V2-6 | **文档删除** | 列表卡片悬停显示删除按钮，二次确认后**彻底删除**（不可恢复，区别于归档的软删除） |
| V2-7 | **自定义弹框** | 用自绘对话框替换浏览器原生 `confirm`/`alert`，统一视觉与交互 |
| V2-8 | **令牌入配置** | （v0.2）agent 令牌从环境变量改为 `config.yaml` 的 `token`；**v0.3 已被 V3-2 取代**，不再使用共享令牌 |

**v0.3 多用户**

| 编号 | 功能 | 说明 |
|---|---|---|
| V3-1 | **自助注册与用户表** | 用户名（`[a-z0-9_-]` 3-32 位）+ 密码（8-72 位）注册；用户表是单个 `users.yaml`（用户名 / bcrypt 密码哈希 / token / 创建时间），放在 `data/` 之外不进备份；`config.yaml` 的 `allow_register: false` 可关闭注册；同 IP 每小时最多注册 5 次 |
| V3-2 | **每用户 token** | 注册时自动生成，Web「MCP 接入」弹窗可查看与重置；废弃共享 `token` / `-token` / `MDBOX_TOKEN`；`-stdio` 需 `-user` 指定为谁服务 |
| V3-3 | **文档按用户隔离** | 每个用户一个目录 `data/users/<username>/{docs,archive}`，对应一个独立 Store；admin 也在 `data/users/admin/` 下 |

## 5. 用户旅程

**旅程 A：人到 see → 改（浏览器）**
打开服务地址 → 登录 → 左侧栏按分类/标签过滤或直接搜索 → 点开文档（默认只读预览）→ 点「编辑」进双栏改源码看效果 → Ctrl+S → 关闭换设备后仍是最新版

**旅程 B：agent 到 see（MCP）**
对话中 agent 需要历史决策 → `search_docs("限流")` → `read_doc(id)` → 基于真实历史内容继续讨论

**旅程 C：分享给人看（免登录）**
点「分享」开启 → 复制固定链接发给同事 → 对方无需登录即可只读浏览 → 不需要时关闭分享，链接即刻 404

**旅程 D：产出归档（P1 目标态）**
讨论结束 → agent 调 `write_doc(title, content, tags)` → 文档进入库 → 人在浏览器里看到、编辑、补充

**旅程 E：生命周期（P1 目标态）**
每周定时任务生成过期清单 → 人确认 → `archive_doc` 移入归档区 → 活跃区保持干净

## 6. 技术方案

### 6.1 架构

```
入口层   Web UI（人）        MCP / REST（agent，脚本）
            │                     │
服务层   HTTP Server ──── REST API ──── MCP Server（共用同一 store）
            │              ├ 元数据索引（内存，启动时全量重建）
            │              ├ 登录会话（内存）+ 分享签名（HMAC）
存储层   data/users/<username>/docs/*.md + frontmatter ← git 自动备份到远端
用户表   users.yaml（data/ 之外）：用户名 / 密码哈希 / 每用户 token
配置     config.yaml：初始账号 / 分享 secret / allow_register
```

### 6.2 数据模型

文件名 `{date}-{random}.md`，内容：

```yaml
---
title: 文档标题
tags: [标签1, 标签2]
category: 分类
source: agent | codebuddy | upload | web
status: active | archived
shared: false          # 是否开启匿名分享（v0.2 新增）
created: 2026-10-01T00:00:00+08:00
updated: 2026-10-01T00:00:00+08:00
---
```

`source` 字段用于后续统计"agent 产出了多少文档"，是产品化阶段的关键数据源。

### 6.3 REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` · `/api/register` · `/api/logout` | 登录 / 注册（成功即登录）/ 退出（下发与清除会话 Cookie） |
| GET | `/api/me` · POST `/api/me/token` | 当前用户及其 token / 重置 token |
| GET | `/api/health` | 健康检查 |
| GET | `/api/docs?tag=&category=&status=&q=&limit=` | 列表 / 搜索 |
| POST | `/api/docs` | 创建 |
| GET | `/api/docs/{id}` | 读取（含正文与渲染后 HTML；已分享时附 shareUrl） |
| PUT | `/api/docs/{id}` | 更新 |
| POST | `/api/docs/{id}/archive` | 归档（软删除） |
| DELETE | `/api/docs/{id}` | 彻底删除（不可恢复） |
| POST | `/api/docs/{id}/share` | 开启/关闭分享，返回固定链接 |
| GET | `/api/docs/{id}/download` | 下载 .md |
| GET | `/api/share/{user}/{id}/{sig}` · `/api/share/{user}/{id}/{sig}/download` | **匿名**只读读取 / 下载（分享） |
| GET | `/api/tags` · `/api/categories` | 聚合 |
| POST | `/api/upload` | multipart 多文件上传 |
| POST | `/api/preview` | Markdown → HTML |

`/s/{user}/{id}/{sig}` 返回分享页 HTML（前端按路径进入只读分享模式）。

### 6.4 MCP 工具

`list_docs` · `search_docs` · `read_doc` · `write_doc` · `update_doc` · `list_tags` · `archive_doc`

接入方式（HTTP，token 是你自己账号的，见 Web「MCP 接入」；每个 token 只能访问其所属用户的文档）：

```json
{ "mcpServers": { "mdbox": { "url": "http://<server>:8080/mcp",
    "headers": { "Authorization": "Bearer <token>" } } } }
```

### 6.5 部署与运维

单二进制交付（前端资源 embed 进可执行文件），Go 1.23+ 构建，无数据库、无外部服务依赖。
配置文件 `config.yaml` 首次启动自动生成（初始账号、分享 secret、allow_register），用户表 `users.yaml` 随首次启动创建，二者均已 gitignore。
数据目录本身是 Git 仓库，`scripts/git-backup.sh` 挂 crontab 定时备份。

**部署约束**：mdbox 是**有状态、单实例**服务（内存索引 + 内存会话 + 磁盘文件），需挂持久磁盘当 `data/`；文档走普通文件系统 I/O，**不适合直接放在对象存储（S3/OSS）上**。

### 6.6 关键选型理由

- **存储用磁盘 + Git，而非数据库**：文档本身要能脱离工具存在；Git 白送版本历史、备份、异地同步
- **预览渲染放服务端**：前端零依赖，不依赖任何 CDN（国内网络环境下很重要）
- **保留源码 + 预览双栏而非 WYSIWYG**：维持 Markdown 的纯粹性与可移植性，同时大幅降低实现与移动端适配成本
- **索引与登录会话在内存**：万篇以内完全够用，换来零部署复杂度
- **分享链接用固定签名算法**（`HMAC(secret, id)`）：同一文档地址恒定、便于转达，且可通过更换 `secret` 一键全量失效

## 9. 风险与开放问题

1. **需求真实性未验证**：所有假设建立在"确实会因为过期清理删掉废稿"之上。若验证期为发现真痛点，应停留在自用工具，不投入产品化。
2. **付费点偏薄**：存储是 Git 免费给的、AI 是用户自己的 agent、编辑器是开源库，可收费的只有"归档与保鲜体验"这一层，能否支撑付费尚未验证。
3. **数据不锁定是双刃剑**：利于获客（信任），不利于留存（迁移成本极低）。
4. **命名与 SEO**：Markdoc 已被 Stripe 的开源文档框架占用（markdoc.dev / markdoc.io），如需对外，品牌名需要重新考虑。
5. **精力分配**：作者同时维护 SellingPilot 与 SmartRouter 两个产品，第三项目标存在明显机会成本。建议将 mdbox 定位为 SmartRouter 的延伸能力/杀手级示例，而非独立产品线。

## 10. 商业化考虑（附录，暂不行动）

若要对外，最现实的路径不是"卖给所有人的知识库"，而是：

- **人群**：重度使用 agent 的开发者与技术团队（正在快速增长，尚无标准答案）
- **形态**：作为 SmartRouter 的增值模块 —— LLM 网关天然缺少持久记忆层，mdbox 正好补上
- **定价假设**：个人免费（Git + 自建），团队版按席位收 USD 订阅，卖点是归档体验和保鲜管理
- **前置条件**：必须先通过 M0.5 自用验证，并且 Runway 与精力都允许
